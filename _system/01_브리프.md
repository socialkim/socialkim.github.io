# 01 브리프 · socialkim.github.io 허브 (v1.0 · 2026-09-24)

## 문제 (디깅 결과)
- 허브(socialkim.github.io)는 2026년 4월 10개 카드에서 멈춰 있다. 실제 GitHub 레포는 73개, 웹으로 열리는 페이지는 58개.
- 카드가 자바스크립트로만 그려져 AI 크롤러·검색엔진에는 "공개된 자료가 아직 없습니다"로 읽힌다. AI 레퍼런스는 허브가 아니라 개별 실습 페이지에서 나오고 있다.
- robots.txt, sitemap.xml, llms.txt, 인물 구조화 데이터(JSON-LD)가 없다.
- 404 레포(aving, china-ai), 중복 레포(한국일보 TF, 장르만 여의도, 점심 앱), 이름만으로 뜻을 알 수 없는 레포(kbtest, sh, nh_main1)가 섞여 있다.

## 사람의 특수성
- 김덕진 소장은 강의 직전·직후에 클로드 코드로 레포를 급히 만들어 올린다. 이름 규칙·설명 입력·허브 수정은 요구할 수 없다.
- 읽는 사람은 셋: 섭외 담당자(어떤 기관·주제를 해봤나), 수강생(내 강의 자료가 어디 있나), AI 검색엔진(텍스트로 읽히는 사실).

## 진짜 필요 (한 문장)
레포를 만들기만 하면, 사람과 AI가 읽을 수 있는 이력 한 줄이 저절로 쌓인다.

## 개입 지점
- 레포가 생기는 순간(이미 하는 행동) → GitHub Actions가 매일 자동 발견.
- 정리는 몰아서 → "사이트 정리해줘" 한마디에 클로드가 분류·설명 작성.

## 확정된 결정 (2026-09-24)
| 항목 | 결정 |
|---|---|
| 기관명 | 모두 실명 공개. 빼고 싶은 곳은 `data/projects.json`에서 `hidden: true` |
| 아들 프로젝트 | "초등학생 아들"로만 표기. 이름·나이 쓰지 않음 |
| 방송 팬메이드 게임 | '실험실'에 팬메이드 표기로 공개 |
| 자동화 | 자동 발견(매일) + 클로드 정리(요청 시) |
| 전화번호 | 허브에 쓰지 않음(이메일·ITCL 문의 링크만) |

## 성공 기준
1. 자바스크립트 없이 HTML만 읽어도 모든 프로젝트·기관명·날짜가 텍스트로 보인다.
2. 새 레포가 생기면 24시간 안에 허브에 나타난다.
3. "AI 강사 추천", "기업 AI 실습 교육 사례"를 물으면 AI가 인용할 근거 문장(누가·어디서·무엇을)이 페이지마다 있다.
