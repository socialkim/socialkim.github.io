가끔 클로드에게 **"socialkim 허브 정리해줘"** 라고 하시면 분류·설명을 다듬어 반영합니다.

## B. 클로드 정리 루틴 (스킬 socialkim-hub-update)
1. `git pull` → `python3 scripts/discover.py`로 inbox 갱신.
2. inbox 항목마다 페이지를 열어 읽고 아래 규칙으로 projects.json에 옮긴다. 중복·테스트는 `_system/02_계획서.md` 제외 목록과 `data/exclude.json`에 추가.
3. `python3 scripts/build.py` → `python3 scripts/check.py`(링크·필수 필드 검사).
4. 커밋 메시지: `hub: +N 추가, M 정리 (YYYY-MM-DD)`. push는 소장님 PC에서.

## C. 분류 규칙
- 강의 대상 조직이 있으면 `lecture`. 기업(금융·제조·유통·투자사 포함)은 `corp`, 정부·공기업·지자체·협회·재단·교회·도서관은 `public`, 대학 수업·교직원·대학원은 `univ`, 언론사는 `media`, 특정 조직 없이 직무 대상이면 `job`.
- 강의가 아니라 쓰는 물건(서비스·MCP·대시보드·컨설팅 페이지)이면 `build`.
- 게임·실험·방송 연계물은 `lab`. 방송 프로그램 이름이 들어간 비공식 게임은 반드시 `label: "팬메이드"`.
- 아들과 함께 만든 것은 `family`. 이름·나이·학교를 쓰지 않고 "초등학생 아들"로만.

## D. 문구 규칙 (소장님 말투 기준)
- 제목은 페이지의 큰 제목을 살린다. 없으면 "기관 + 무엇" (예: "LH 실무자 AI 실습 워크북").
- summary는 두 문장 이내. 첫 문장 = 누구를 위해 무엇을, 둘째 문장 = 무엇을 따라 할 수 있는지.
- 대시(—)와 별표 강조, "혁신적인·획기적인" 같은 과장어를 summary에 쓰지 않는다.
- 금액·전화번호·수강생 개인정보·비공개 자료 내용은 싣지 않는다.
- 날짜는 페이지에 적힌 강의일 우선, 없으면 레포 생성일.

## E. 새 실습 페이지를 만들 때 넣으면 좋은 한 줄 (선택)
실습 페이지 맨 아래에 아래 조각을 넣으면, 개별 페이지에서도 허브로 이어지고 AI가 저자를 정확히 연결합니다.
```html
<footer style="text-align:center;font-size:13px;color:#667;padding:24px">
  IT커뮤니케이션연구소 김덕진 소장 · <a href="https://socialkim.github.io/">강의·프로젝트 전체 보기</a>
</footer>
<script type="application/ld+json">{"@context":"https://schema.org","@type":"LearningResource","name":"페이지 제목","author":{"@type":"Person","name":"김덕진","url":"https://socialkim.github.io/about/"},"isPartOf":{"@type":"WebSite","url":"https://socialkim.github.io/"}}</script>
```

## F. 디자인 규칙 (개인 브랜드 방향 J "네이비와 하늘")
- 색: 종이 #FAFBFC, 네이비 잉크 #0F1B2D, 코발트 #2457C5(링크·버튼), 하늘 #57D0FF(배지·짧은 선), 하늘 옅음 #EAF7FE, 빨강 #E5261F는 로고 점에만.
- 글꼴: Pretendard(한글), Space Grotesk(영문 워드마크), JetBrains Mono(라벨·날짜).
- 카드 하나 = 기관 · 제목 · 요지 한 줄 · 날짜. 이모지 아이콘 쓰지 않음.

## G. GitHub 밖에서 만든 작업 (2026-09-24 추가)
- ChatGPT 사이트(*.socialkim.chatgpt.site), Vercel 등 GitHub Pages가 아닌 곳의 작업은 자동 발견되지 않는다. 소장님이 링크를 주면 클로드가 읽고 projects.json에 넣는다.
- `made_with`에 만든 AI를 적는다(`ChatGPT`, `Claude` 등). 카드와 상세 페이지에 배지로 표시된다.
- 날짜를 알 수 없으면 `date`를 비워 두거나 `YYYY-MM`으로 적는다. 추측한 날짜는 쓰지 않는다.
- 생성 문장이 맞지 않는 항목(분석 페이지, 북토크 등)은 `claim`에 근거 문장을 직접 쓴다.
